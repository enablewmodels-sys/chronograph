# C# / .NET SDK

Requires .NET 8+. Add a project reference to `sdk/csharp/Chronograph/Chronograph.csproj`. NuGet publication has not occurred; the package metadata for it is prepared (see [Publishing to NuGet](#publishing-to-nuget-maintainers)).

```csharp
using Chronograph;
using System.Text.Json.Nodes;

using var client = new Client(Environment.GetEnvironmentVariable("CHRONOGRAPH_URL")!,
    Environment.GetEnvironmentVariable("CHRONOGRAPH_TOKEN")!);
var page = await client.CallAsync("as_of",
    new JsonObject { ["t"]="9007199254740993", ["limit"]=100 });
Console.WriteLine(page.ToJsonString());
```

`CallAsync`, `RequestAsync`, `IngestAsync` and `CheckpointAsync` accept `CancellationToken`. `ApiException` exposes `Status`, `Code` and `RetryAfter`. The constructor accepts `TimeSpan? timeout` and `int maxResponseBytes`. Reuse a Client for connection pooling; dispose it when finished. `RequestAsync` returns bounded bytes for binary exports. To build a local package, run `dotnet pack sdk/csharp/Chronograph`; the license and notice are included.

This is an alpha.3 source package for the Chronograph Community `/v1` API, not a published package-registry release. Read the [SDK guide](../../docs/SDK.md), [platform recipes](../../docs/INTEGRATIONS.md) and [HTTP API reference](../../docs/API.md).

All IDs and microsecond timestamps are decimal strings. `call` exposes JSON operations; `request` handles GET/DELETE and bounded binary responses. No application write retries are performed. Defaults: 30-second timeout, 4 MiB request/response caps. Remote origins require HTTPS; redirects are rejected. Increase the response cap explicitly for larger Arrow/backup downloads (maximum 256 MiB).

## Publishing to NuGet (maintainers)

**Nothing has been published to nuget.org.** `ChronoDB.Client` `0.4.0-alpha.3` is a
source package. The project file now carries the metadata `dotnet pack` needs:

- `PackageId` `ChronoDB.Client` and `Version` `0.4.0-alpha.3`, matching the Python (`0.4.0a3`), TypeScript, Dart and Java SDKs
- `Title`, `Authors` and `Company` (IntelliNxT), `Product`, `Copyright`, `Description`, `PackageTags`
- `PackageProjectUrl` <https://chronodb.co>, `RepositoryUrl`, `RepositoryType` git and `PublishRepositoryUrl` for the embedded commit
- `PackageLicenseFile` LICENSE and `PackageReadmeFile` README.md, with LICENSE, NOTICE and README.md packed at the package root
- `PackageReleaseNotes` pointing at CHANGELOG.md, and `IsPackable` true

```sh
dotnet pack sdk/csharp/Chronograph -c Release -o /tmp/nupkg
# the package root should list LICENSE, NOTICE and README.md
unzip -l /tmp/nupkg/ChronoDB.Client.0.4.0-alpha.3.nupkg
dotnet nuget push /tmp/nupkg/ChronoDB.Client.0.4.0-alpha.3.nupkg \
  --api-key "$NUGET_API_KEY" --source https://api.nuget.org/v3/index.json
```

### Why a licence file instead of `PackageLicenseExpression`

PolyForm Perimeter 1.0.0 is not an SPDX expression, so `PackageLicenseExpression` cannot be
used and would fail packing. The package declares `PackageLicenseFile` LICENSE instead and
packs the unmodified licence text plus the `Required Notice:` lines from NOTICE. In the
nuspec this appears as `<license type="file">LICENSE</license>`, and the gallery shows the
licence as "see LICENSE".

### Blockers before the first push

1. **nuget.org account and API key.** A push needs an account with a scoped API key; never
   commit or paste the key.
2. **Package ID ownership.** nuget.org has no `ChronoDB.Client` package today, but it
   does host an unrelated `Chronograph` (owner aL1fe) and a `Chronograph.*` family (owner
   Ironic). If Ironic has a reserved `Chronograph.*` ID prefix, nuget.org rejects submissions
   from other owners that match it. Confirm this on the gallery with the publishing account,
   or publish under a company-owned prefix such as `IntelliNxT.*`.
3. **Unverified build.** The .NET SDK is not installed in the workspace where this metadata
   was written, so `dotnet pack`, the resulting nuspec and a fresh restore of the package
   have not been run. The nuspec under `sdk/csharp/Chronograph/obj/Release/` was generated by
   an earlier build and predates these edits.
4. **Licence acceptance.** `PackageRequireLicenseAcceptance` is left at the NuGet default
   false so restore never prompts. Set it to true if every consumer must acknowledge the
   noncompeting-use restriction before installing.

## BCI and binary data

Use your isolated origin or `https://chronodb.co` and a scoped project key.
Managed routes the origin to the key's project; `/p/PROJECT_ID` is not an SDK
constructor URL. Record session `101` first using the [acquisition guide](https://chronodb.co/documentation/BCI).
The following uses the `client` from the connection example above:

```csharp
var window = await client.BCIWindowAsync("bci_research", "101", "eeg", "0", "1000000", new JsonArray(0, 1));
await foreach (var page in client.PagesAsync("bci_records",
    new JsonObject { ["instance"]="bci_research", ["session"]="101" }, maxPages:200)) {
    Console.WriteLine(page.ToJsonString());
}
```

`UploadAssetAsync(byte[], metadata)` / `ReadAssetAsync(id)` handle 1 byte–16 MiB of exact binary data.
Chunk lengths, metadata and pagination progress are checked; malformed responses
fail explicitly. Page iteration is incremental with a configurable 1–10,000 page
budget. Stop consuming (or return false from a callback) to stop fetching.

`bci_sessions`, `bci_session`, `bci_records`, `bci_window` and `bci_manifest` are
shared API operations. All model connectors use the same normalized records,
asset helpers and explicit ingest sequence. BrainFlow/LSL device acquisition and
MNE/CSP training run in the Python acquisition service, not in this HTTP client.
