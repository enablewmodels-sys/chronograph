# Supported scope and known limits

Community has tested temporal semantics, durable branches, connector adapters and an authenticated local service. The limits below describe Community. [Managed hosting](HOSTED.md) adds a separate account and project control plane, with its own documented boundaries. Both remain previews; this candidate does not establish a production certification or hard real-time deadline guarantee.

- One workspace journal, one owning process and one writer at a time. Tokens grant workspace-wide read/ingest/admin scope. There are no user accounts, teams, hosted signup, SSO, OAuth provider, replication or shared-engine multi-tenancy.
- Directed typed edge versions with fixed 16-byte payloads. No SQL/Cypher/property query language, temporal node labels, vector/spatial index, automatic inference or general tensor store. Structured connector rows use immutable Arrow sidecars through explicit mappings.
- All history and indexes are rebuilt in memory after journal replay. Startup and memory grow with retained versions. There is no compaction, retention policy, history pruning or sidecar garbage collection. The checked explicit codec replaces the earlier bincode format; format-1 migration preserves the source and writes a separate destination.
- Full graph as-of/interval queries scan retained versions. Neighborhood indexes reduce local work, but no worst-case deadline is promised. Service readers, writes, backups and Arrow exports share one lock; a long read can delay a write.
- Forks freeze the active-at-time state. Identical parent revision/time forks share a base; the first distinct base scans parent history and known nodes. There are no nested forks, rebases or automatic conflict resolution. Any parent revision change blocks merge, as does touched pre-existing future information. Limits: 256 active forks, 65536 lifetime fork records, 80-byte names and a 64 MiB atomic merge/frame bound. Closed metadata remains; opaque payload IDs are not rewritten.
- HTTP/MCP merge results are capped at 10000 total node/edge mappings. Use the embedded API for larger eligible merges. A branch edge ID must always be paired with its selected fork; it is not a parent edge ID.
- Browser graph rendering shows at most 40 nodes and 80 edges from the query page. Pages are bounded to 1000 rows. The main timeline slider is an explicit 0–4-second sample range; exact fields accept the full signed i64 range. Branch queries reject times before their fork point. The initial branch list shows at most 1000 metadata records; the API supports further ID-based pages.
- There are no retained MVCC transactions across HTTP pages, insertion idempotency keys or graph/auth cross-store transactions. Any global graph mutation invalidates a cursor. Inspect state before retrying an ambiguous insertion or fork creation. Merge/discard retain their successful lifecycle results for safe retries after reopening.
- The service uses HTTPS through a reverse proxy for remote origins. It does not supply at-rest encryption, actor audit trails, storage quotas, Prometheus metrics or automatic off-host backups. Rate/body/worker bounds protect admission but do not reserve memory or disk capacity.
- HTTP Arrow export accepts at most 1M stored versions in the selected parent/fork and materializes a result batch. Use the embedded library for larger offline exports. Local archives are limited to 3 retained files, 100 GiB and 10000 members per archive.
- BCI simulation and native synthetic LSL loopback passed; real hardware and cross-host synchronization are unverified. Robotics supports bounded JointState plus explicit video references; it does not decode arbitrary ROS messages or materialize video tensors. World-model support uses fixed-length observations, discrete actions and explicit complete-state codecs. Quantum support is a static unitary OpenQASM subset and calibration windows, not a QPU integration. The individual connector guides specify all rejection and size bounds.
- MCP HTTP/native stdio interoperability passed with the official SDK client. Supplied Codex/Cursor/Claude configurations are documented, but interactive sessions in each application remain unverified. OAuth-only hosted connectors require additional infrastructure.
- Final candidate measurements missed the 2M batch-ingest and <10 ms as-of median targets: 1.10M/s and 19.053 ms on this M5 with AC Low Power Mode enabled. Single-ingest and sampling targets passed. Earlier checkpoint power state was not recorded, so a controlled baseline comparison is still needed. Warm-cache timings do not establish performance on other machines or service/network latency. Neo4j comparison remains pending while Docker is unavailable. [Benchmark evidence](BENCHMARKS.md).

Community source is published on GitHub. The private Managed control plane is deployed with HTTPS, accounts, MFA, bounded project provisioning, roles, API/MCP routing, a secret vault and scheduled local backups. Billing, automated off-host recovery, dedicated tenant isolation and an uptime SLA are not implemented.
